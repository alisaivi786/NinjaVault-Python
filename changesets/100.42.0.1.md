# ninjavault-cdn 100.42.0.1

Date: 2026-09-28
Type: Major

## Changes
- First public release on PyPI as `ninjavault-cdn` (import `ninjavault_cdn`).
- Feature parity with the .NET package `NinjaVault.Cdn` 100.42.0.1: access validation (`get_access_context`),
  bucket discovery, multipart upload, file listing/search, metadata, usage summary, authenticated streaming
  download (`download`, `download_to`), soft delete, public URL building, and single/batch presigned URLs.
- Two clients with the same surface: `NinjaVaultCdnClient` (sync, `httpx.Client`) and
  `AsyncNinjaVaultCdnClient` (async, `httpx.AsyncClient`). Both are context managers.
- Configuration via keyword arguments or `NINJAVAULT_CDN_BASE_URL`, `NINJAVAULT_CDN_API_KEY` and
  `NINJAVAULT_CDN_PUBLIC_BASE_URL`; a missing setting raises a `ValueError` naming it.
- Request URLs are built from `base_url` directly, so a path prefix (`https://host/cdn`) works. Bucket names and
  every object-key segment are percent-encoded like .NET `Uri.EscapeDataString`.
- CDN error envelopes map to `CdnApiError` (status code, error code, description, `traceId` as
  `correlation_id`, validation `details`, `retry_after` from delta-seconds or HTTP-date `Retry-After`).
  Non-JSON error bodies are mapped too. Network failures raise `CdnConnectionError` / `CdnTimeoutError`.
- `ErrorCode` `IntEnum` with 40001, 40101, 40301, 40401, 40901, 42901, 50001.
- Frozen, slotted dataclass models that ignore unknown fields; unknown enum values are kept as strings; timestamps
  are timezone-aware; numeric tenant ids are `int` and GUID tenant ids stay `str`.
- `delete` accepts `204 No Content`, an empty body, or a success envelope; a `success: false` envelope raises.
- `build_public_url` accepts a `public_base_url` that already ends in `/public` without producing `/public/public/`.
- DEBUG logging on the `ninjavault_cdn` logger (method, URL, status, elapsed ms; never the API key or file bytes).
  `event_hooks` or your own `http_client` for application logging and `X-Correlation-Id`.
- `User-Agent` is `ninjavault-cdn-python/<version>` (plus an optional `user_agent_suffix`).
- Fully typed (`py.typed`), Python 3.10 to 3.14, only runtime dependency `httpx>=0.27,<1`.

## Why
- Let Python teams integrate with the NinjaVault CDN Server by installing one package instead of hand-rolling
  API-key headers, multipart fields, object-key encoding and the JSON envelope.

## Breaking Changes
- None (first public release).
